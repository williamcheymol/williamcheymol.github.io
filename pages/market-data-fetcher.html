QUANT DATA PYTHON

Market Data
Fetcher

A reusable Python data layer for quantitative finance — pulling, cleaning and structuring historical market data via yfinance into formats ready for backtesting and analysis.

THE PROBLEM

Quantitative finance projects — pricers, hedging simulations, risk models — all share a common need: clean, structured price data. Yet sourcing and preparing that data is always the same tedious work: download from an API, handle errors, clean NaNs and splits, compute returns.

The goal of this project is to build that layer once and build it right — a modular pipeline that takes a ticker and a date range as input, and outputs a clean DataFrame enriched with the financial features that quant analysis actually needs.

It works on any ticker supported by yfinance — stocks, ETFs, indices, crypto, forex — and handles the full cleaning chain automatically: duplicate dates, invalid prices, missing values, dividend and split adjustments. The output is a clean, enriched DataFrame ready for downstream use, with no post-processing required.

It is designed as a reusable foundation for the broader project series — the delta-hedging simulation and the BS pricer both rely on exactly this kind of structured data.

fetcher/download.py

Download

download_single() and download_multiple() — pull OHLCV data from Yahoo Finance with auto_adjust=True (corrects for dividends and splits). Multi-ticker loop skips failing tickers gracefully instead of crashing. Handles MultiIndex columns that yfinance sometimes produces.

cleaner/pipeline.py

Clean

Four sequential steps: remove duplicate dates (keeping last), remove invalid prices (zero or negative close), fill missing values via forward-fill (last known price), then standardise column names to lowercase OHLCV across all ticker types. A single NaN propagates downstream — cleaning is not optional.

features/compute.py

Features

Computes log-returns $r_t = \log(S_t/S_{t-1})$, rolling realised volatility (annualised by $\sqrt{252}$, 21-day window), and cumulative returns $\exp(\sum r_i) - 1$. All features connect directly to the Black-Scholes / GBM framework used in the delta-hedging project.

exporter/export.py

Export

Saves one CSV per ticker to the results/ folder. The output format is designed for direct consumption by backtesting engines, numerical pricers, or ML pipelines — no post-processing required.

KEY TECHNICAL CHOICES
LOG-RETURNS
$$r_t = \log\!\left(\frac{S_t}{S_{t-1}}\right)$$
Preferred over simple returns because they are additive across time: $r(0 \to T) = \sum r(t \to t+1)$. Approximately normally distributed and directly compatible with Black-Scholes / GBM assumptions — the same increments used in the delta-hedging Monte Carlo paths.
REALISED VOLATILITY
$$\hat{\sigma}_t = \sqrt{252} \cdot \text{std}_{[t-21,\, t]}(r)$$
Rolling standard deviation of log-returns, annualised by $\sqrt{252}$. Measures what the market actually did, as opposed to implied volatility (what the market expects). The gap between the two is the foundation of volatility smile analysis.
